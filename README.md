# SmartSchool

React + Vite school-management platform, ready for Supabase and Vercel.

1. Copy `.env.example` to `.env` and add your Supabase URL and anon key.
2. Run `npm install`, then `npm run dev`.
3. Apply `supabase/schema.sql`, then every numbered SQL migration in order (`002` through `042`) in the Supabase SQL Editor.
4. Set `SMARTSCHOOL_ALLOWED_ORIGINS` as a Supabase Edge Function secret to a comma-separated list of exact app origins, then deploy registration and invitation functions with `supabase functions deploy register-school` and `supabase functions deploy manage-school-user`. Include local origins only for development. These functions use the service-role secret only server-side; never add that secret to frontend environment variables.
5. Enable email confirmation and configure the Auth email templates and redirect URL for your local and production app URLs.
6. Add the frontend environment variables in Vercel and deploy.

School registration creates a pending school and its initial administrator. The school administrator can only access setup and subscription details until the platform Super Admin approves the school; student, teacher, and parent portals remain unavailable until approval. After approval, each school administrator manages accounts and branding for that school's portals. Each role signs into its own portal. Subscription plan records are managed manually; payment checkout is not integrated yet.

The teacher portal is organized around assigned classes, attendance, assignments, gradebook, lesson planning, timetable, quizzes, courses, and library access. Additional school duties are assigned separately and appear in the Staff portal hub; finance, HR/payroll, admissions, inventory, and academic leadership tools are shown only to staff with the matching role. Health, counselling, transport, and boarding are identified as future specialist modules and are not represented as active workflows yet.

Migration `027_role_security_hardening.sql` scopes school records by role and relationship, limits SuperAdmin analytics to aggregate counts, and moves quiz grading into the database. Migration `028_school_report_periods.sql` adds academic year and term data to exams for report cards. Migration `029_school_registration_rate_limit.sql` adds a service-role-only registration throttle. Apply all migrations to the Supabase project before using the updated school portals. Payment screens provide school payment instructions but do not confirm transactions.

After applying migrations `027` and `039`, run `supabase/tests/tenant-isolation.manual.sql` in the Supabase SQL Editor to check cross-school reads and writes for assets, expenses, staff attendance, and payment reconciliation. It requires at least two schools with administrator accounts and rolls back its fixture data. Migration `040_privileged_mfa_enforcement.sql` requires AAL2 MFA for privileged data changes in the database as well as in the application.

## Mobile app and TypeScript

SmartSchool can be installed as a Progressive Web App. Build and preview it with `npm run build` and `npm run preview`; the production preview exposes the install prompt for student, teacher, and parent accounts. Browser storage caches only the app shell and static assets. School records and portal data remain online and are never added to the offline cache. On iOS, use Share → Add to Home Screen.

The existing React app remains the shared client for all role portals. TypeScript is enabled for incremental migration of shared modules; run `npm run typecheck` before building. Authentication, role routing, and school-brand color helpers are the first typed modules. The Capacitor dependencies remain available for a later native wrapper, but native Android/iOS projects and their notification credentials have not been generated or configured.

See `docs/security-and-product-hardening.md` for the MFA, session cleanup, onboarding checklist, outbound delivery worker, and provider setup notes. `docs/backup-and-recovery.md` contains database, Storage, and restore-drill instructions.

The HR & Payroll portal is available to school administrators and teacher accounts granted an HR role. Migration `037_hr_payroll_core.sql` creates the school-scoped HR, salary, payroll, approval, and payment-tracking records. Principal salary and payroll approval require verified MFA; payroll approval records a hash of the submitted payroll version. Payroll preparation uses principal-approved salary records and requires human review for leave and statutory adjustments. Migration `038_country_and_school_payment_setup.sql` adds tenant country, general currency codes, time zones, and each school’s own bank/mobile-money payment instructions. Migration `039_operations_security_and_finance.sql` adds staff attendance, controlled expense records, manual payment reconciliation with duplicate-reference protection, inventory history, finance audit events, and RLS migration assertions. Migration `041_school_role_assignments.sql` adds multi-role school staff assignments and a shared permission catalog while preserving the primary portal roles; school administrators assign roles from Staff roles & access. Migration `042_workflow_access_and_delivery.sql` adds subject-scoped assignment and assessment access, private student assignment uploads, grade limits, specialist wellbeing access, push registration, and retrying notification delivery. Bank and mobile-money transfers, SmartSchool subscription checkout, contract file storage, and payslip PDF generation still require provider and private-storage configuration.
